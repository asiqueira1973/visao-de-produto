O PROBLEMA

Você entrega feature toda semana e não sabe qual tela é usada.

Não é falta de ferramenta. É que nenhuma delas foi feita para quem não está procurando ferramenta — quem constrói com o Claude Code, a partir de specs, e não vai passar a tarde comparando tabela de preço.

01

Nada é capturado automaticamente

Sem IP, sem geolocalização, sem user-agent, sem pageview implícito. Só existe aqui o que o seu código enviou de propósito. É o contrário do padrão do mercado, e é deliberado.

02

Todo evento carrega o que significa

A descrição em português é campo de primeira classe. Seis meses depois, crm_lead_qualificado continua dizendo “vendedor marcou o lead como qualificado” — para você e para o agente.

03

O evento que não aconteceu aparece

Com zero explícito. Você subiu uma feature na semana passada; a tela mostra que ela nunca foi usada. É a pergunta que as outras ferramentas escondem.

COMO FUNCIONA

Três passos, e um deles
você nem faz.

1

O agente instrumenta enquanto constrói

Ao implementar uma tela nova, o Claude adiciona a chamada de evento no código, seguindo a convenção que o projeto já usa e escrevendo a descrição em português. Você revisa o diff como revisa qualquer outro.

PacienteNovo.tsx · diff
+ track("crm_lead_criado", {
+   descricao: "vendedor cadastrou um lead novo",
+   tela: "Funil"
+ });
2

O app envia — pelo SDK ou direto pela API

Uma chamada com a chave do projeto. Quem já faz POST não instala pacote nenhum. O SDK dá fila offline, reenvio e lote automático; a chamada direta funciona em qualquer linguagem.

3

Você pergunta — no painel ou no Claude

Pelas telas, quando você quer olhar. Pelo Claude, quando a pergunta aparece no meio do trabalho e você não quer trocar de janela. As duas formas leem os mesmos dados.

No painel Atividade, Uso, Painel, Pessoas, Catálogo
No Claude via MCP, com token de leitura
